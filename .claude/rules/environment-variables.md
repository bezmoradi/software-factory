# Environment variables

Configuration is loaded from `.env` at the project root (via `godotenv`). Real shell environment variables take precedence over `.env`, so you can override any key inline (e.g. `PORT=9000 make run`).

- `PORT` — HTTP listen port (default `7799`; the image sets 8080 inside the container).
- Engine, Docker edition: `SF_PAGE_HOST`, `SF_PAGE_NAME` (with `SF_PAGE_HOST=0.0.0.0`: the name whose addresses the page accepts besides loopback), `SF_PUBLIC_PORT`, `SF_COMPOSE_PROJECT` (the stack's Compose project, which `compose.yaml` fills in from `COMPOSE_PROJECT_NAME`, so the commands the engine and the page show carry `-p <project>`; a value that isn't a Compose project name is ignored with a warning, and the commands then leave out `-p`), `SF_REVIEWS` (the engine's path to the reviews volume; unset, or without `SF_HELPER`, no review runs; each reviewer container sees its snapshot at `/reviews/<id>`), `SF_REVIEWER_PROXY` (the proxy a reviewer container reaches, default `egress-review:3128`), `SF_VERIFY` (the engine's path to the verify volume, `/verify` in `compose.yaml`, where it writes each verification run's files and command; unset, or without `SF_HELPER`, no verification runs), `SF_DEV_REVIEWER` (development only: the fake reviewer's path in the reviewer containers, run in place of `claude`; the engine logs a warning when it is set), `SF_DEV_REVIEW_MINUTES` (development only: a whole number of minutes, 1 to 19, after which a reviewer run times out in place of 20; honoured only in an image with the development marker file, logged with a warning, and ignored with `review event=dev-timeout-ignored` elsewhere; any other value stops the engine's start; `compose.dev.yaml` passes it from your shell), `SF_STATE_DIR`, `SF_WORKSPACE`, `SF_AGENT_ADDRESS` (the agent listener, `0.0.0.0:8081` in `compose.yaml`; it keeps only connections from running sessions' containers), `SF_HELPER` (the box helper, `helper:8099`, or `off`; without it the engine starts no sessions, and it refuses to start while the old `SF_AGENT_HOST` is set), `SF_HELPER_KEY_FILE` (where the engine writes the helper's key hash and TLS pair at each start, default `/run/sf-helper/key`), `SF_BOX_SUBNETS` (the session containers' address pool, as the helper reads it, which the page's address mustn't fall in), `SF_EGRESS_PROXY`, `SF_EGRESS_STATUS`, `EGRESS_ALLOW`, `EGRESS_DENY`, `SF_SANDBOX_CHECK`, `SF_SANDBOX_OUTSIDE`, `SF_AGENTS_DIR`, `SF_AGENTS_INSTALL` (`start`, the default, or `manual`: the start installs no agent and doesn't check knackpack's `main`, so it makes no network call for them; `install-agents` does both), `SF_DEV_KNACKPACK_URL` (development only: an https URL whose `main` the engine follows for knackpack in place of `https://github.com/bezmoradi/knackpack.git`, trusted through `SF_DEV_GIT_CA`, such as the dev git host's stand-in, `https://gitserver.test:8443/public/knackpack.git`; honoured only in an image with the development marker file, otherwise ignored with one `plugin install event=dev-source-ignored` line; a value that isn't an https URL with a path stops the engine's start; the engine logs a warning; `compose.dev.yaml` passes it from your shell, and `make proctor`'s `up.sh` sets it), `SF_NPM_REGISTRY` (the npm registry the agents are installed from, default `https://registry.npmjs.org`: an `https` URL with no path, which must also serve the tarballs and the attestations from its own host; the install follows no redirect to another host or scheme), `SF_UMASK`, `SF_UPLOADS` (the engine's path to the uploads volume), `SF_AGENT_UPLOADS` (the agents' path to it, under which each session's container sees its own `<box>` folder), `SF_PLUGIN_DIR` (the Software Factory plugin in a session's container), `SF_AGENT_BINARY` (the `software-factory` binary in a session's container, for `mcp` and `sandbox-probe`, or `off`), `SF_DEV_ACP_AGENT` (development only: the ACP agent's absolute path in a session's container, offered as the development agent; the engine gives its sessions a check-only key, `SF_DEV_CHECK_KEY`, only when the value is exactly `/usr/local/bin/sf-fake-acp` and the image has the development marker file, and otherwise logs `check-key-ignored`; ARCHITECTURE.md's "Trust boundary" has the rest), `SF_DEV_SKIP_SIGNIN` (development only: `1` signs a page in without a code; start the development overlay with `SF_DEV_SKIP_SIGNIN=1 COMPOSE_FILE=compose.yaml:compose.dev.yaml docker compose up -d --build`) and `SF_DEV_GIT_CA` (development only: a PEM file of CAs the engine trusts for clones and fetches besides the system's; the engine logs a warning when it is set).
- agent-host: `SF_AGENT_HOST_MODE` (or `-mode`: `agent`, or `review` in a reviewer container, where it takes its key once from the engine at `/v1/key` and then needs it on every route but `/healthz`), `SF_WORKSPACE`, `SF_AGENT_HOST_LISTEN`, `SF_AGENT_HOST_MAX_PROCESSES`, `SF_ENGINE_AGENT_ADDRESS`, `SF_PLUGIN_SOCKET`, `SF_AGENTS_BIN`, `SF_GIT` (the git program for worktrees, default `git`), `SF_UMASK`. Roles in a session's container never read `.env`. agent-host gives each Claude Code session its own `SF_PUSH_TOKEN`, which the engine makes; don't set it. `SF_AGENT_HOST_LISTEN` defaults to `127.0.0.1:8090`; the box helper sets `:8090` in each session's and reviewer container, so the engine reaches them on their networks. **Run outside Docker,** agent mode answers every route, `/v1/run` (which runs a command) included, to anyone who can reach its port: keep it on loopback and widen it only when the engine runs on another machine or in a container. Reviews need the box helper, which makes their containers, so they don't run outside Docker.
- egress: `EGRESS_LISTEN` (the agents' proxy, default `:3130`, which answers only the session containers' subnets the engine sets over the control channel), `EGRESS_REVIEW_LISTEN` (a second proxy for the reviewers, with its own `EGRESS_MAX_CONNS`, so agents can't use up the reviews' connections; and it answers only the reviewer containers' subnets the engine sets; Compose sets `0.0.0.0:3128`, and `EGRESS_LISTEN` to `0.0.0.0:3130`, while a session's container reaches egress as `egress` and a reviewer container as `egress-review`, the `.3` of its own network in its `/etc/hosts`), `EGRESS_STATUS_LISTEN`, `EGRESS_ALLOW`, `EGRESS_DENY`, `EGRESS_MAX_CONNS`, `EGRESS_IDLE_TIMEOUT` (default `5m`), `EGRESS_MAX_DURATION` (default `1h`).
- Box helper (`software-factory box-helper`, the `helper` service): `SF_HELPER_LISTEN` (default `:8099`), `SF_HELPER_KEY_FILE` (where it reads the engine's key hash and TLS pair, default `/run/sf-helper/key`), `SF_BOX_MEMORY` (each session's container's memory and memory with swap, `256m` to `256g`, default `2g`), `SF_BOX_CPUS` (`0.1` to `256`, default `2`), `SF_REVIEWER_MEMORY` and `SF_REVIEWER_CPUS` (the same for each reviewer container, the same defaults), `SF_MAX_BOXES` (the most session containers running or starting at once, `1` to `256`; unset means no limit; reviewer containers don't count, and the helper runs at most 32 of them), `SF_BOX_RUNTIME` (unset, or `runsc`, which `compose.gvisor.yaml` sets; a start is refused while Docker lists no such runtime), `SF_BOX_SUBNETS` (IPv4 networks of `/8` to `/28`, separated by commas, cut into one `/28` per container, default `10.213.0.0/20`; the helper refuses to start when they overlap a Docker network or its default address pools, and the engine reads the same value), `SF_VERIFY_MEMORY` (each verification container's memory and memory with swap, `256m` to `256g`, default `4g`; its files' scratch folder counts against it), `SF_VERIFY_CPUS` (`0.1` to `256`, default `2`), `SF_VERIFY_DISK` (the size of that scratch folder, `/work`, a tmpfs, `64m` to `256g`, default `2g`, and never more than `SF_VERIFY_MEMORY`, to which a larger value is cut), `SF_VERIFY_MINUTES` (a verification run's time limit, a whole number of minutes from `1` to `120`, default `15`; the helper kills a run that passes it, and the engine counts such a run as out of time; the helper runs at most 4 verification containers at once, the engine 2), `SF_BOX_SWEEP_DRY` (`1`: the start-up sweep logs `would_remove` and removes nothing) and `SF_BOX_LIVE` (development only: `1` mounts the `dev-bin` volume read-only into each new container and runs its binary; honoured only in an image with `/usr/share/software-factory/dev-image`, the `dev` stage's, and otherwise ignored with one `live_ignored` log line; `compose.live.yaml` sets it, and the release check refuses it). The helper also reads `HOSTNAME`, which Docker sets to its container's ID. Compose fills two of its settings from your shell: `SF_DOCKER_SOCKET` (Docker's socket on the Docker host, default `/var/run/docker.sock`, bind-mounted at `/var/run/docker.sock`) and `SF_DOCKER_GID` (the socket's group, added to the helper's user, default `0`: Docker Desktop's; `stat -c %g /var/run/docker.sock` on Linux, `2375` in `docker:dind`; `make up` and `make dev` fill it in when it's unset, with `stat` in a throwaway container of the image that mounts the socket, so the value is the group containers see). After an install from a release, the install script writes both into `software-factory-socket.yaml` instead.
- The control channel: `SF_EGRESS_KEY_FILE` in the engine, where it writes the SHA-256 of a new control key at each start, and `EGRESS_CONTROL_KEY_FILE` in egress, where egress reads it; Compose sets both to `/run/sf-egress/control-key` on the `egress-key` volume. Beside it the engine writes a new TLS certificate and key (`control-cert.pem`, `control-tls-key.pem`) at each start, and egress serves its control listener with them over TLS 1.3. With either unset, the allowlist is only `EGRESS_ALLOW`, the listener is plain HTTP and Network access answers 501. The engine refuses to start with `SF_HELPER` set and `SF_EGRESS_KEY_FILE` unset, since egress then drops every session's traffic; with only `EGRESS_CONTROL_KEY_FILE` unset, the sandbox check fails. Egress also reads `SF_BOX_SUBNETS`, and takes only session networks inside it.
- Development state switches: `SF_DEV_STATE_VERSION` (`2` makes `savedprompts.json` write and read format 2, so a saved prompt leaves a copy in `backup/`, which an engine without it reads after the rollback step) and `SF_DEV_AUDIT_ROTATE` (a size in bytes, 1024 or more, at which the audit rotates, so a dropped-records notice shows quickly); the engine logs a warning for each, and `compose.dev.yaml` passes both from your shell.
- Update check: `SF_NO_UPDATE_CHECK` (`1` stops the engine's check for a newer release at `api.github.com`, every 24 hours and at a start whose stored check is 24 hours old or more, and the page can't turn it on; any other non-empty value counts too; `compose.yaml` passes it from your shell) and `SF_DEV_UPDATE_API` (development only: an https base URL the check asks in place of `https://api.github.com`, trusted through `SF_DEV_GIT_CA`, such as the dev git host's fake, `https://gitserver.test:8443/release-api`; honoured only in an image with `/usr/share/software-factory/dev-image`, otherwise ignored with one `dev-api-ignored` line; honoured, it also shortens the reuse of a stored check at start to one minute; the engine logs a warning; `compose.dev.yaml` passes it from your shell and runs the engine on the `dev` image for it). `docs/reference/runs-and-operations.md` "The update check" has the rest.
- Advisories: `SF_OSV` (`off` stops the engine's lookup of the pinned Claude Code version and the installed knackpack commit at `api.osv.dev`, 30 seconds after start and every 24 hours, and its lookup of the CVE and GHSA IDs a review's message cites), `SF_DEV_OSV` (development only: an https base URL the cited IDs are looked up at instead of `api.osv.dev`, trusted through `SF_DEV_GIT_CA`, such as the dev git host's fake, `https://gitserver.test:8443/osv`; the engine logs a warning; `compose.dev.yaml` passes it from your shell) and `SF_DEV_ADVISORY_PIN` (development only: `<npm package>@<version>` looks that pinned package up at another version, such as `@anthropic-ai/claude-code@1.0.20`, which has advisories, so the page's notice can be seen; the engine logs a warning; `compose.dev.yaml` passes it from your shell).

`scripts/release-check.sh` refuses a release configuration that names any `SF_DEV_` variable, anywhere in it, so no development switch ships in a release's Compose files.

The `.env` file is git-ignored and optional: a clone has none, and `make run` needs none.
