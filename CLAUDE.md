# Working on Software Factory

Read `AGENTS.md` for the layout, the dependency rule and the commands, and `ARCHITECTURE.md` for how the product works and why.

## Rules

- **No code reads, stores, logs or passes a model credential:** no token file, keychain entry or key variable, and no call to a vendor's OAuth endpoint. Every process the engine starts gets the key variables cleared (`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`, `OPENAI_API_KEY`, `CODEX_API_KEY` and the like). Reason: each agent must be the vendor's own unmodified binary, signed in by the person with the vendor's own mechanism; vendors' terms forbid products that reuse or route through those sign-ins. The one credential the engine holds is the git host token the person gives it for pushing. Two exceptions, the owner's decisions of 2026-11-12: the page's Claude Code sign-in passes the one-time code the person pastes from claude.com to Claude Code's own `claude auth login` in the agent or reviewer container; and it passes an Anthropic API key the person pastes to that container's agent-host, which saves it in a file only that container's user can read and points Claude Code's own `apiKeyHelper` setting at it. The engine keeps, logs and shows back neither. Whether Anthropic's terms allow the first wasn't checked.
- **The engine never runs a `git` command line.** It reads `.git` files itself and pushes with a Go git library. Reason: a repository's configuration (`core.fsmonitor`, hooks, diff drivers, credential helpers) names programs git runs, and agents can write `.git`.
- **Nothing from the agent network is trusted as a decision, a verdict or a push.** The engine accepts only reports and requests from it, and refuses what the page doesn't offer. Reason: anything in the agent container, Claude Code's plugin included, may be run by an agent acting on planted instructions (`ARCHITECTURE.md` "Trust boundary").
- **After any change to the page server** (`internal/adapters/http/page`, `cmd/server`), **run the page's security checks with curl** (`ARCHITECTURE.md` "Page security checks") against the running server. Reason: they keep other sites and processes from driving the page, and only a real request shows the headers and limits actually sent.
- **No automated tests: don't add `*_test.go` files or `testdata`.** Reason: the owner chose no test strategy. Check a change with the build, `go vet`, `make lint`, `make arch-check`, `make fix-check`, `make vuln`, `make web-check`, `make plugin-check`, `make plugin-validate`, and a live run with `compose.dev.yaml`. A bypass a review finds is fixed and recorded in the change's description, since no test keeps it from coming back.
- **No comments, in code or configuration:** Go, TypeScript, JavaScript, CSS, HTML, shell, YAML (workflows and compose), Dockerfile, Makefile, TOML and the linters' configuration. Two exceptions: the version comment after a pinned commit SHA or image digest (`uses: actions/checkout@<sha> # v7.0.1`), which Dependabot and reviewers read, and tool directives, which the tools treat as instructions rather than comments (`//go:build`, `//go:embed`, `//nolint:…`, `// Code generated … DO NOT EDIT.`, shebangs, `# syntax=` in the Dockerfile). Reason: the owner's choice. Put an explanation in a name, in `AGENTS.md` or `ARCHITECTURE.md`, or in the change's description.
- **Commit only when the owner asks. Never push, add a remote or publish an image.** Reason: the owner decides what becomes public and when.
- **Outside libraries are allowed, pinned (`go.sum`, an npm lockfile) and under licenses compatible with MIT.** Reason: Software Factory is MIT-licensed.
